# Шаблоны промптов по типам задач

> Раздел Практикума. **Проверено: 2026-06.** Копируйте шаблон, подставляйте своё в `[квадратные
> скобки]`, проверяйте вывод. Это не магия — это [метод + проверка](index.md). У каждого шаблона внизу —
> строка **«Что проверить»**: без неё промпт даёт демо, а не результат.

Общая рамка всех шаблонов — **роль · цель · контекст · формат · граница · что проверить**. Обезличивайте:
убирайте имена, реальные цифры и чувствительные данные, оставляйте суть. Не отправляйте в сторонние
сервисы то, что не должно туда попасть.

---

## 1. Разобрать документ

```
Ты [роль: юрист на моей стороне / аналитик / редактор]. Я — [контекст: заказчик / автор].
Вот документ: [вставьте текст].
Задача: выдели [риски / неясности / ключевые условия] для меня.
Формат: таблица — пункт · суть · почему важно для меня · цитата из текста · предложение.
Границы: не сглаживай неоднозначное; если чего-то нет в тексте — так и скажи, не додумывай.
```
**Что проверить:** цитаты сверьте с оригиналом; решение и ответственность — на вас.

## 2. Сравнить варианты и выбрать

```
Подбери [N] вариантов [чего] под мои ограничения: [бюджет, размеры, совместимость, сроки, доступ из РФ].
Для каждого: для какой задачи подходит и один честный риск/минус.
Не давай длинный список — только [N] и почему именно они.
```
**Что проверить:** цены, наличие и характеристики — на дату, по первоисточнику (их модель выдумывает).

## 3. Сгенерировать черновик (письмо / пост / ответ)

```
Аудитория: [кто]. Их боль/интерес: [какой]. Моя цель: [что должно произойти].
Дай [N] вариантов [письма / поста], тон [спокойный, деловой, без хайпа].
Не выдумывай факты/цифры обо мне или продукте — где не знаешь, оставь пропуск [...].
```
**Что проверить:** факты и цифры — ваши; вычитайте тон и уберите канцелярит под себя.

## 4. Найти слабые места (критика, не подтверждение)

```
Найди причины, по которым [решение / план / кандидат / компания] — плохая идея.
Будь строг: ищи [риски, дыры, причины отклонить], а не доводы «за».
Отметь, что из этого можно проверить заранее и как.
```
**Что проверить:** вы решаете по сумме «за и против»; модель лишь расширяет список «против».

## 5. Объяснить / научить по уровням

```
Объясни [тему] на трёх уровнях: ребёнку, новичку в профессии, коллеге.
Веди меня вопросами, не давай всё сразу. После каждого блока — один вопрос на закрепление.
Где есть распространённое заблуждение — отметь его.
```
**Что проверить:** для важных тем (медицина, право, финансы) — сверяйте с первоисточником/специалистом.

## 6. Извлечь структуру из текста

```
Вытащи из этого текста [сущности: суммы, даты, имена, задачи] в таблицу: [колонки].
Форматы бывают разные — приводи к одному. Сомнительные строки помечай отдельно.
Ничего не добавляй от себя; чего нет в тексте — оставляй пустым.
```
**Что проверить:** пройдите выборкой 10–15 строк — в одной почти наверняка ошибка.

## 7. Разложить задачу на шаги / план

```
Цель: [что хочу получить] к [срок]. Ограничения: [время, ресурсы, что нельзя].
Разложи на шаги: что сделать первым, что можно отдать ИИ, что оставить за собой.
Для каждого шага — точка проверки. Дай один следующий ход на эту неделю, не весь список сразу.
```
**Что проверить:** реалистичность сроков и зависимостей — на вас; план — гипотеза, не истина.

## 8. Подготовиться к разговору / встрече (dry-run)

```
Контекст встречи: [с кем, о чём, моя цель]. Роли участников: [CFO / клиент / руководитель].
Сыграй вторую сторону: задавай мне сложные вопросы и возражения по одному.
В конце — какие 3 аргумента у меня слабые и что подготовить.
```
**Что проверить:** это репетиция, не сценарий; живой разговор пойдёт иначе.
