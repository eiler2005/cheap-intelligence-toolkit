# Воркшоп: первый агент команды — контракт за 90 минут

> Командная версия листа [«Контракт с агентом»](../playbooks/agent-contract.md) (Том 2, глава 3).
> Участники: команда функции, куда приходит агент (4–8 человек), включая тех, кто боится, что
> «агент — это про сокращения». Их присутствие — не риск, а половина смысла сессии.

**Результат сессии:** заполненный контракт одного агента — роль, границы, эскалация, проверка,
порог-стоп, владелец — плюс список случаев для будущего [эталонного набора](../playbooks/eval-set-builder.md).

## Подготовка (ведущему)

- Выбран процесс (в идеале — из [воркшопа по скорингу](process-scoring-workshop.md)).
- Шаблон контракта из [листа](../playbooks/agent-contract.md) — на доску, 10 полей пустыми.
- Два примера из листа (агент поддержки, агент-аналитик) — под рукой.

## Агенда 90 минут

| Время | Блок | Как |
|---|---|---|
| 0–10 | Рамка | «Агент — не волшебный сотрудник, а роль с границами и владельцем. Сегодня мы решаем, чего он **не** делает». Страхи — легальны, для них блок в конце. |
| 10–20 | Роль и миссия | Одним предложением: зачем агент существует. Если предложение не выходит — процесс не готов, честно вернуться к скорингу. |
| 20–40 | Границы и эскалация | Сначала молча: каждый пишет 3 вещи, которые агент «никогда без подтверждения», и 3 сигнала «немедленно человеку». Потом сводим. Здесь говорят те, кто знает худшие случаи, — обычно не руководитель. |
| 40–55 | Проверка и порог-стоп | Как проверяем результат (кто, сколько в день, по какому чек-листу — не «ИИ проверит ИИ»). Одно число-порог и действие на нём: пауза / откат / стоп. |
| 55–70 | Память, входы, доступы | Минимум доступа для миссии (least privilege). Что агенту запоминать нельзя (персональные данные, секреты). |
| 70–80 | Люди | Прямо: что меняется в ролях команды. Кто ведёт базу знаний, кто аудитит агента — это новые задачи, назвать поимённо. |
| 80–90 | Владелец и pre-flight | Один человек — владелец (не «команда»). Чек-лист pre-flight из [листа](../playbooks/agent-contract.md) вслух. Фото контракта. |

## Домашнее задание команды (одна неделя)

Каждый участник приносит **5 реальных случаев из истории** процесса с известным правильным
исходом — включая 1–2 «страшных». Это заготовка [эталонного набора](../playbooks/eval-set-builder.md):
20+ случаев соберутся за неделю без отдельного проекта.

## Грабли

- **Контракт без порога-стопа** — пожелание, а не контракт. Число называется до запуска
  (см. [разбор Klarna](../playbooks/klarna-compass-example.md) — что бывает, когда порог
  срабатывает через прессу).
- **Владелец «мы все»** = владельца нет.
- **Границы пишет только руководитель.** Худшие случаи знает первая линия — их «никогда без
  подтверждения» ценнее.
