# Цепочка хранения: первые сутки с важным файлом

> Практикум к **Тому 3, главе 10**. Время: 10–15 минут.
> Это бытовой протокол первой сохранности, а не цифровая экспертиза и не юридическая консультация.

Важный файл редко проигрывает спор потому, что выглядит недостаточно убедительно. Чаще проблема
проще: неизвестно, откуда он взялся, менялся ли после появления и кто держал его в руках. Задача
этого листа — сохранить варианты. Он не гарантирует, что банк, редакция или суд примут файл, но
не даёт вам самим уничтожить полезный след.

---

## Сначала: четыре действия

### 1. Сохраните оригинал

- Заберите исходный файл с устройства или сервиса, где он появился.
- Не делайте пересылку через мессенджер единственной копией: сервис может сжать файл или убрать
  часть метаданных.
- Создайте рабочую копию, а оригинал положите отдельно и больше не редактируйте.
- Сохраните соседний контекст: переписку, письмо, карточку звонка, чек, журнал входов.

**Запишите путь к оригиналу:** ________________________________________________

### 2. Запишите «кто, когда, что»

| Дата и время | У кого был файл | Что с ним сделали | Кому передали / где сохранили |
|---|---|---|---|
| | | | |
| | | | |
| | | | |

Заполняйте журнал сразу. Собственный журнал можно дописать задним числом, поэтому сам по себе он
ничего не доказывает. Его ценность в другом: он связывает файл с независимыми следами — письмом,
облачной историей, банковским обращением, номером заявления.

### 3. Зафиксируйте файл независимо

Выберите соразмерный цене ошибки способ:

- **Контрольная сумма** показывает, что два файла совпадают побитно. Она не доказывает автора и
  сама по себе не доказывает дату.
- **Канал с внешним временем** — корпоративная система, облачная история версий, зарегистрированное
  обращение — помогает показать, что файл уже существовал к определённому моменту.
- **Специалист или нотариус** нужен не «на всякий случай», а когда спор уже вероятен и цена ошибки
  высока.

**Контрольная сумма / внешний след:** __________________________________________

### 4. Не улучшайте оригинал

Шумоподавление, апскейл, монтаж и команда «сделай почётче» создают производную версию. Она может
быть удобнее для просмотра, но уже не равна тому, что записало устройство.

- Оригинал остаётся нетронутым.
- Улучшенная или обрезанная версия получает другое имя.
- В журнале записывается, чем и зачем создана производная копия.

## В течение первых суток

- [ ] Сообщить банку в тот же день, если затронуты деньги; сохранить номер обращения.
- [ ] Сохранить банковскую выписку, чек и данные получателя.
- [ ] Экспортировать переписку или письмо вместе с датами и служебными заголовками, если они
      доступны.
- [ ] Записать имена людей, которые видели событие или файл.
- [ ] Попросить сохранить журналы системы, если доступ к ним есть у работодателя, площадки или
      подрядчика.
- [ ] При вероятном споре обратиться по адресу: деньги и мошенничество — банк и полиция; договор
      или работа — юрист; публикация — проверочная редакция.

## Что обычно ослабляет файл

- единственная копия — пересылка или скриншот;
- переименование без записи исходного имени;
- монтаж поверх оригинала;
- удаление соседней переписки и уведомлений;
- длинная пауза до первого независимого обращения;
- уверенность «на записи всё и так видно».

Основа протокола — рекомендации
[NIST SP 800-86](https://www.nist.gov/publications/guide-integrating-forensic-techniques-incident-response):
действия с цифровым материалом фиксируют, исходник сохраняют, целостность проверяют. Сам NIST
предупреждает, что это практическое руководство по компьютерной криминалистике, а не юридическая
инструкция для любой страны.
